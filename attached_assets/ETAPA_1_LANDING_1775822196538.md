# Expo Miami Real Estate — Etapa 1: Landing + Registro SIMA
## Documento de producto para desarrollo en Replit
### Stack: React + Vite · Express · SQLite · Multer

---

## Objetivo de esta etapa

Tener un sitio web público en producción que:
1. Presente la marca Expo Miami Real Estate al mercado español
2. Muestre Miami visualmente con fotos de impacto
3. Capture leads de personas interesadas en reunirse en el SIMA Madrid 2026
4. Tenga un panel admin simple para gestionar las imágenes del sitio

---

## Alcance — qué se construye en Etapa 1

```
✓ Web pública (landing page completa)
✓ Formulario de captura de leads SIMA
✓ Panel admin con login (usuario + clave)
✓ Mantenedor de imágenes del sitio
✓ Base de datos para guardar leads
✗ NO incluye: galería de proyectos (Etapa 2)
✗ NO incluye: scraper de propiedades (Etapa 2)
✗ NO incluye: ficha interior de proyectos (Etapa 2)
```

## 4. Base de datos — Etapa 1

Solo dos tablas necesarias para esta etapa:

### Tabla: `leads`
```
id               — autoincremento
name             — nombre completo
email            — email (requerido)
phone            — teléfono
capital_range    — rango de capital seleccionado
investment_stage — momento de inversión
source           — origen (siempre "sima-form" en esta etapa)
created_at       — fecha y hora de registro
```

### Tabla: `site_settings`
```
key        — identificador único (ej: "hero_image", "tagline")
value      — valor actual (texto o ruta de imagen)
type       — "text" | "image" | "html"
label      — nombre legible para el admin
section    — agrupación: hero | scenes | about | sima | global
hint       — resolución recomendada (para imágenes)
updated_at — última actualización
```

### Tabla: `admin_users`
```
id         — autoincremento
username   — nombre de usuario
password   — hash bcrypt
created_at — fecha de creación
```

## 5. Flujo de imágenes — resumen técnico

```
Admin sube imagen
      ↓
Servidor recibe el archivo (Multer)
      ↓
Sharp redimensiona y optimiza
(máx dimensión según sección, calidad 85%, formato JPG)
      ↓
Guarda en /server/uploads/{sección}/
      ↓
Actualiza site_settings con la nueva ruta
      ↓
La web pública lee /api/settings
y muestra la imagen actualizada
```

**Carpetas de uploads:**
```
server/uploads/
  ├── hero/       → imagen de portada
  ├── scenes/     → 4 escenas de Miami
  ├── about/      → foto del equipo
  └── logos/      → logo y favicon
```

## 6. API necesaria — Etapa 1

Solo los endpoints imprescindibles:

```
POST /api/auth/login          → devuelve JWT token
GET  /api/auth/me             → verifica sesión activa

GET  /api/settings            → devuelve todos los settings agrupados (público)
GET  /api/admin/settings      → igual pero con metadatos (admin)
PUT  /api/admin/settings      → actualiza un setting de texto
POST /api/admin/settings/image → sube y reemplaza una imagen

POST /api/leads               → guarda un nuevo lead (público)
GET  /api/admin/leads         → lista leads (admin)
GET  /api/admin/leads/export  → descarga CSV (admin)

GET  /api/admin/stats         → números resumen para dashboard
```

## 10. Notas importantes para el desarrollador

- Las imágenes se sirven desde `/uploads/` como archivos estáticos
- Al subir una imagen nueva, la anterior NO se elimina automáticamente
  (se puede limpiar manualmente desde la carpeta o agregar esta función en Etapa 2)
- El formulario de leads NO envía email automáticamente en Etapa 1
  (agregar integración con email en Etapa 2 si se necesita)
- El número de WhatsApp en el botón se configura desde admin (site_settings)
- En Replit, la carpeta `server/uploads/` persiste entre reinicios del servidor
- La base de datos SQLite también persiste en Replit automáticamente
